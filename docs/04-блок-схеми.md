# 04 — Блок-схеми

Схеми відображають рішення, ухвалені в [03](03-пріоритети-та-конфлікти.md). Якщо схема і документ 03 розходяться, істиною є 03.

**Синхрон з виконуваним графом:** `protocol/graphs/zero-echelon-core/` (`graphVersion` `2026-10-05-witness-info`, плюс `engine-rules.json` з `civilianSafeMode.enabled: true`). Зміна екрана без правки графа / rules — дефект процесу (див. [13](13-структура-репозиторію.md)). Півот і відновлення лікування: [stakeholder/півот-цивільний-безпечний.md](stakeholder/півот-цивільний-безпечний.md).

**Активний продукт (civilianSafeMode):** Home → Disclaimer → Loc → Type → Role (цивільний свідок) → фіксація ознак A\* без наближення → Observe-count / Observe-signs → A6 (обмеження програми) → Call 112 → **Safe-civil** → Form / Give / Handed / Wave. **101** на екранах небезпечної зони. Дерева лікування **B–G** і модуль **J** лишаються в `graph.json`, але **приховані**. Повернути: `civilianSafeMode.enabled: false`.

Гілки позначені літерами: A — безпека сцени (активна), H — звіт і передача (активна), I — друга хвиля (активна), **Safe-civil** — цивільний безпечний лендінг після Call. B — сортування, C — кровотеча, D — дихання, E — грудна клітка, F — тривале стискання, G — психологічна підтримка, J — щоденний модуль — **архів / вимкнено civilianSafeMode** (не активний шлях продукту).

## Головна схема

Активний шлях SKU «безпечний свідок». Ребра Count → Care / Casualty-menu **немає** при `civilianSafeMode.enabled: true`.

```mermaid
flowchart TD
  Start["Відкриття: ярлик або посилання"] --> Home{"Home: що потрібно?"}
  Home -->|"щось сталось зараз"| Disc["S0 Дисклеймер"]
  Disc --> Loc["Loc-mode: GPS або адреса вручну"]
  Home -->|"чек-лист після події"| WaveIn["I: друга хвиля"]
  Loc --> Type["Тип події з піктограм"]
  Type --> Role{"Цивільний свідок: спостерігаю / стосується мене"}
  Role --> Safety{"A: ознаки небезпеки, видимі звідси, без наближення"}
  Safety --> CountVis["Скільки людей видно звідси"]
  CountVis --> SignsVis["Ознаки без контакту"]
  SignsVis --> A6["A6: програма не дає фізичних вказівок"]
  A6 --> Call["Виклик 112. Чернетка на екрані"]
  Call --> SafeCivil["Safe-civil: фіксація і передача службам"]
  SafeCivil --> Form["H: Form — звіт"]
  Form --> Read["Read: зачитати чернетку диспетчеру"]
  Form --> Give["Give: показати текст + QR медику"]
  Form --> HandedF["Handed: передав медику"]
  Form --> Erase["Erase: стерти локальний журнал"]
  Form --> Wave["I: чек-лист / таймери 24 і 48 год"]
  Give --> HandedG["Handed"]
  HandedF --> Keep["Лишити журнал → Home"]
  HandedF --> Wipe["Стерти → Home"]
  HandedG --> Keep
  HandedG --> Wipe
```

Зверніть увагу.

1. Активний цивільний шлях **не** наказує відходити, наближатися, перевіряти предмети чи надавати допомогу. Ознаки «так» ідуть у звіт.
2. **Немає** ребра «підійти допомогти біля снаряда» (K5).
3. Виклик 112 — після фіксації видимого; далі **Safe-civil**, не сортування і не індивідуальна допомога.
4. Службової розвилки немає. Користувач — **цивільний свідок**.
5. **Home** — лише дві кнопки: «Щось сталось зараз» і «Чек-лист після події». Вхід **daily** (J) **прихований** (`hiddenHomeWhens`). Повний дисклеймер (S0) лише на шляху гострої події; I заходить без нього.
6. Місце: **GPS** або **адреса вручну одним рядком**. QR на стіні немає. QR на Give — чернетка звіту медику.
7. При `civilianSafeMode.enabled: true` interrupt **A7** під час допомоги B–G не активний у продукті (дерева сховані). Після відновлення лікування (`enabled: false`) A7 знову застосовується за `engine-rules`.
8. Після Call «Далі» → **Safe-civil** → Form. Після Form/Give — **Handed**: лишити журнал для 24/48 або стерти → Home. UI-рамка: top bar = бренд/Назад + голос + налаштування (мова не в top bar) — див. [12](12-екрани-та-специфікація.md).
9. Екстрені номери в UI: **112**; на вето-екранах — **101**. Номера **103** у продукті немає.

## A. Безпека сцени

Порядок вузлів **залежить від типу події** (`engine-rules.json` → `safety.queuesByIncidentType`). Нижче — повний набір загроз; для ДТП, наприклад, черга `A4 → A3 → A5 → A6` (без UXO A1).

```mermaid
flowchart TD
  A0["Старт черги загроз для обраного типу"] --> Threats["A1 UXO · A2 обвал · A3 дим/газ · A4 дроти · A5 речовина"]
  Threats -->|"так на будь-якій"| CanLeave{"Можете відійти, не чіпаючи?"}
  Threats -->|"ні / не бачу → наступна в черзі"| A6["A6: закривальний наказ ЗА ТИПОМ"]
  CanLeave -->|"так"| Out["Відхід 100-300 м. Нічого не чіпати. 101. Звіт: недосяжні"]
  CanLeave -->|"ні"| OutTrap["Не чіпати. Не смикати. Не звільняти. 101. Звіт: я/люди тут"]
  A6 --> Call["Call / 112"]
```

**A6 (голос залежить від типу, не лише «завал»):**

| Тип | Сенс наказу |
| --- | --- |
| ДТП (`traffic`) | Не на проїзджій; аварійка; не чіпати проводи |
| Пожежа | Не в дим/полумʼя; з навітряного боку; не відкривати гарячі двері |
| Хімія | Не чіпати рідину; не нюхати; проти вітру |
| Побут | Вимкнути джерело, якщо безпечно |
| Вибух / завал / потяг / стрілянина | Не в завал; не рухати уламки |

**A7** — періодичний interrupt під час допомоги після того, як сцена вже пройдена (`armAfterLeavingNodeId: A6`, інтервал з rules). Відповідь «загроза» → CanLeave. У SKU з `civilianSafeMode` допомога B–G не показується — A7 актуальний лише після відновлення лікування.

Після «Так» на загрозі **немає** медичної гілки і **немає** «підійти до поранених». CanLeave розрізняє лише можливість відійти (K5a).

## Safe-civil — цивільний безпечний лендінг (після Call)

Активний вузол продукту. Після Call «Далі» рушій веде сюди (не в Count / Casualty-menu). Текст: не надавати медичну допомогу за вказівками додатка; після влучання / тривоги — не заходити в зону; викликати 112; далі — звіт.

```mermaid
flowchart TD
  Call["Call / 112"] --> Safe["Safe-civil"]
  Safe -->|"Далі / Відкрити звіт"| Form["H: Form"]
```

## C. Масивна кровотеча

> **Архів / вимкнено civilianSafeMode.** Вузли в графі (`blockedBranches: C`). Не активний шлях продукту.

```mermaid
flowchart TD
  C0["Ознаки: фонтанує, калюжа крові, одяг просякнутий, повʼязка промокає"] --> C1{"Є хоч одна ознака?"}
  C1 -->|"ні"| Skip["Перейти до гілки D"]
  C1 -->|"так"| C2["Негайно сильний прямий тиск руками на рану"]
  C2 --> C3{"Травматична ампутація, повна або часткова?"}
  C3 -->|"так"| Tq["Турнікет незалежно від наявності кровотечі"]
  C3 -->|"ні"| C4{"Кровотеча на кінцівці і є комерційний турнікет?"}
  C4 -->|"так"| Tq
  C4 -->|"ні"| Pack["Тампонада рани будь-яким чистим матеріалом, зверху прямий тиск"]
  Tq --> TqRules["Вище рани, не на суглоб, не на відкритий перелом. Таймер стартує автоматично"]
  TqRules --> Still{"Кровотеча триває?"}
  Still -->|"так"| Second2["Другий турнікет ближче до тулуба. Перший не послаблювати"]
  Still -->|"ні"| Hands
  Pack --> Hands{"Треба йти до інших постраждалих?"}
  Hands -->|"так"| Deleg["Делегувати руки людині зеленої категорії"]

```

Вузол делегування — не зручність, а вимушене рішення: MUCC забороняє втручання, які змушують залишатися біля постраждалого, а безперервний тиск займає руки на всі 20–30 хвилин.

## D. Дихання і положення

> **Архів / вимкнено civilianSafeMode.** Вузли в графі (`blockedBranches: D`). Не активний шлях продукту.

```mermaid
flowchart TD
  D0{"Дихає нормально?"}
  D0 -->|"ні"| D1{"Був вибух або є проникне поранення?"}
  D1 -->|"так"| NoCpr{"Кілька постраждалих?"}
  NoCpr -->|"так"| NoCprGo["NoCpr: ідіть до наступного"]
  NoCpr -->|"ні"| NoCprStay["NoCpr-stay: залишайтесь, 112"]
  D1 -->|"ні"| Cpr["Компресії 100-120 за хвилину, глибина 5-6 см, без вдихів"]
  D0 -->|"так"| D2{"Свідок залишається поруч і може спостерігати?"}
  D2 -->|"так"| Sup["На спині. За потреби висування нижньої челюсті"]
  D2 -->|"ні"| Lat["Бічне положення. Прохідність важливіша за відсутній нагляд"]
  Sup --> Neck["Шию не фіксувати руками силоміць. Перевертати лише як єдине ціле і з помічником"]
  Lat --> Neck
  Cpr --> Metron["Метроном і великий візуальний лічильник"]
```

**NoCpr (draft K3):** дві ситуації. Кілька постраждалих — «йдіть до наступного». Один або роль casualty — «залишайтесь, 112». Потребує рецензії медика.

Розвилка D2 — найризикованіше продуктове рішення документації (виведена з умов ERC/TECC, не дослівна цитата). Потребує рецензії спеціаліста (draft K4).

## H. Звіт M/ETHANE і передача

Поля M/ETHANE збираються по ходу сценарію; на **Form** користувач обирає дію передачі. Мережі / ЕСОЗ немає. У безпечному режимі після Call користувач потрапляє сюди через **Safe-civil** (без SALT / турнікета з дерев B–G).

```mermaid
flowchart TD
  Fields["Поля з сесії: місце, тип, роль, …"] --> Form["Form: читабельна чернетка"]
  Form --> Read["Read: зачитати диспетчеру"]
  Form --> Give["Give: текст + QR медику"]
  Form --> Handed["Handed: передав медику"]
  Form --> Erase["Erase: стерти журнал зараз"]
  Form --> Wave["wave → I0 чек-лист після події"]
  Give --> Handed
  Handed --> Keep["Лишити для 24/48 → Home"]
  Handed --> Wipe["Стерти журнал → Home"]
  Give --> Mis["Медик вносить у МІС під КЕП зі слів / з екрана"]
```

**Статус реалізації (синхрон з клієнтами):** читабельна чернетка (тип · місце · роль · ключові факти; поля SALT N / турнікет — з архівних дерев, якщо режим лікування увімкнено знову), QR, Handed keep/erase, локальний журнал однієї події і нагадування 24/48 — у MVP. PDF і хеш-ланцюг — ще ні (див. [08](08-звіт-M-ETHANE-та-передача.md)). Обґрунтування офлайн-передачі — [10](10-право-регуляторика-ліцензії.md).

## I. Друга хвиля

Входи: Home → wave; Form → wave; локальний таймер/пуш 24 і 48 год (клієнт). Активний шлях продукту.

```mermaid
flowchart TD

  I1 -->|"так"| Go["Передайте ознаки службам. Викличте 112"]
  I1 -->|"ні"| I2{"Темна сеча, стало менше сечі, наростаючий біль і набряк кінцівки?"}
  I2 -->|"так"| Go
```

## J. Щоденний модуль
