# Розширення продукту — «Лінія 24»

Сюди потрапляє **вхідна концепція розширень** (майстер-план, маніфест для ІІ, аналоги державних програм), **до** того, як вона стає каноном у `docs/01`–`13`.

## Навіщо окрема папка

У репозиторії вже є канонічна документація продукту (**Zero Echelon** / бренд **Line 24**). Вхідний текст часто змішує:

1. те, що **вже зафіксовано** і реалізується;
2. **бажане розширення** (мапи, кешбек, SOS-маяк, гіди Київщини);
3. **промпт для ІІ** (маніфест для генерації коду);
4. **маркетингові / партнерські** тези для КОГА чи Брюсселя.

Якщо все одразу писати в `01`–`13`, зламається доказова дисципліна: у каноні кожне твердження має джерело. Тому intake → gap → окреме рішення «приймаємо в продукт / відкладаємо / відхиляємо».

## Як читати цей каталог

1. [що-вже-є.md](що-вже-є.md) / [one-pager.html](one-pager.html) — **віддати партнерам**: що вже в додатку і що пізніше.
2. [gap-аналіз.md](gap-аналіз.md) — внутрішня розкладка конфліктів.
3. [майстер-план.md](майстер-план.md) — чотири стратегічні блоки, привʼязані до канону.
4. [світовий-досвід.md](світовий-досвід.md) — які назви країн можна казати назовні.
5. [ai-маніфест.md](ai-маніфест.md) — виправлений промпт для ІІ.

Для зовнішньої презентації брати one-pager + [11](../11-пілот-та-валідація.md) §1, не gap.

## Правила роботи з цим матеріалом

1. **Не копіювати медичні формулювання з маніфесту в код**, поки вони не пройшли через [02](../02-реєстр-протоколів.md) і [03](../03-пріоритети-та-конфлікти.md).
2. **Маніфест для ІІ** можна вставляти в модель як контекст, але лише виправлену версію з [ai-маніфест.md](ai-маніфест.md). Відповіді ІІ перевіряти проти канону репо.
3. Нові фічі з майстер-плану спочатку — у `.cursor/specs/` або в журнал рішень gap як «прийнято», і лише потім — у `01`–`13`.
4. Зовнішні презентації будувати з [one-pager.html](one-pager.html) і [11](../11-пілот-та-валідація.md) §1.
